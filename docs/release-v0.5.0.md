# tianshu-mcp v0.5.0 发布说明

**核心主题**：新增**可选视觉验收模块**——把页面截图对比与静态图片规格检查接入现有的「开发 → 验收 → 返修 → 再验收」闭环。未启用视觉模块的项目行为完全兼容。

本版本为 **MINOR**：新增功能与两个 MCP 工具，未破坏已有工具参数、报告字段或验收配置格式；旧报告与旧任务快照仍可读取。

## 新增

### 视觉验收模块（可选，默认关闭）

在项目 `.tianshu-mcp/acceptance.json` 增加 `visual` 对象并设 `enabled: true` 后，`run_task` / `verify_task` 自动带上独立视觉维度；未配置或显式 `enabled: false` 时沿用原有验收方式。

- **三种互斥页面来源**：`existing`（本机已有 HTTP/HTTPS 服务，不管理其进程）、`command`（结构化命令与参数启动服务，跨平台进程树清理，Windows 隐藏窗口）、`static`（临时 HTTP 托管项目子目录，系统分配端口，拒绝目录穿越与项目外符号链接）。
- **截图与交互**：`viewport` / `fullPage` / `element` 三种模式；声明式 `click` / `input` / `hover` / `scroll` / `wait` 步骤；就绪流程固定（隔离上下文 → 导入登录态 → 声明式步骤 → 字体与图片就绪 → 关闭动画与过渡 → 应用屏蔽 → 采样至相邻两次一致）。首版不接受任意 JavaScript 准备脚本。
- **稳定化**：最多 3 次采样、取相邻一致；整页模式有界滚动触发懒加载；持续扩张、超像素预算或无法稳定即阻塞。屏蔽区域必须在报告列明，配置了却定位不到、或全图屏蔽都不通过。
- **像素对比**：统一 PNG；尺寸不同直接失败（不缩放不裁切）；屏蔽区域不计入分子分母；`pixelmatch` 抗锯齿差异默认排除；通过条件为 `不同像素数 / 有效像素数 <= maxDiffRatio`；连通区域分析输出坐标、面积与标注图，最多保留面积最大的 100 个区域并记录其余数量与整体包围框。
- **静态图片规格**：显式列出文件；校验编码格式与扩展名一致、存在非空且可完整解码、EXIF 方向归一后的宽高、宽高比、字节数、可选 DPI 与透明度（按真实透明像素判定）。检测到 GIF/SVG/动画 WebP/APNG 或不支持格式明确报告。解码前先查元数据与尺寸上限。
- **登录态导入**：测试 Cookie 与按 origin 分组的 localStorage；报告只记录是否加载成功，不复制状态内容。
- **网络策略**：仅本机 HTTP/HTTPS 入口；外部字体、图片、接口与 WebSocket 来源必须显式放行；重定向后继续校验；资源被拦截时报告阻塞与来源，不截取残缺页面后假通过。
- **浏览器生命周期**：默认使用显式安装的固定版本浏览器，也支持本机 Chrome/Edge 或指定可执行路径；独立临时用户目录与独立验收实例，不连接日常浏览会话；托管浏览器缺失时阻塞并给出安装命令，不偷偷改用本机浏览器；结束、超时、取消与 MCP 关闭时清理本次创建的页面、浏览器、服务与临时目录。

### 基准管理与冻结

- **两阶段**：`prepare` 生成候选（候选 ID、内容摘要、目标路径、预览报告，存于 MCP 数据目录）；`approve` 核对候选摘要、原基准摘要与当前配置摘要后原子写入正式基准与 manifest。
- **默认目录结构**：`<baselineRoot>/<platform>/<browserKind>/<caseId>/<viewportId>.png`，manifest 记录浏览器完整版本、系统信息、视口、DPR、有效截图配置、参考图摘要与批准信息。
- **缺基准只能生成候选，不能判定视觉通过**；自动返修不调用批准入口；候选被修改、原基准已变化、候选来自其他项目一律拒绝；批准与任务执行使用项目级锁防并发覆盖。
- **规则冻结**：任务动工前保存视觉配置与基准内容摘要，每轮前后核对（关闭视觉、删改规则、更换基准都会被发现并阻塞）；变化需通过独立 `rules review` / `rules approve` 重新建立快照。

### MCP、CLI 与报告

- 新增两个 MCP 工具，均为有副作用的 `write` 操作并标记需要宿主审批：
  - `prepare_visual_baseline`：输入项目路径、可选检查项/视口列表与参考图导入映射，返回候选 ID、摘要与预览位置。
  - `approve_visual_baseline`：输入候选 ID、预期摘要、批准说明与可选阻塞任务 ID，核对后采用基准并按需更新任务快照。
- 新增 CLI 子命令 `tianshu-mcp visual`：`init`、`browser install`、`doctor`、`baseline prepare/approve`、`rules review/approve`、`artifacts clean`。CLI 在建立 MCP stdio 连接前分流，正常 MCP 启动的 stdout 继续只承载合法协议消息。
- **报告扩展**：`VerifyReport` 新增可选 `visual` 字段与 `files.html`，视觉结果含检查 ID、页面/图片类型、视口、`passed`/`failed`/`blocked`/`skipped` 状态、`optional`、稳定原因码、说明、耗时、实际指标、有效规则、浏览器与系统环境、差异区域、屏蔽区域、产物与是否可自动返修。视觉禁用时省略新增字段。
- **离线 HTML**：按检查项与状态浏览、基准/实际/差异并排、叠加透明度控制与差异区域定位；只使用本地产物与内联资源、正确转义文本、不依赖 CDN，图标使用 SVG。
- 每轮产物位于 `<MCP数据目录>/tasks/<taskId>/visual/<reportRound>/`；报告轮次由统一任务级锁分配，自动验收、手动验收与恢复共用，保留全部历史轮次。

### 结论与恢复语义

- 统一结论优先级：用户取消/服务器中断 → 配置或完整性错误/必需检查阻塞 → 必需检查真实缺陷（按 `autoFixRounds` 返修）→ 全部通过。
- 页面不可达、浏览器缺失、基准待批准、资源被拦截、截图不稳定属于**阻塞**，进入 `needs_attention` 并保留「待重新验收」标记；布局差异、图片规格错误、可定位的交互失败属于**缺陷**，进入返修。
- `rework_task` 对视觉阻塞任务**先重新验收、不先启动开发 agent**：通过即结束，仍阻塞则回到 `needs_attention`，只有出现真实缺陷才消耗返修预算。
- 通用返修计划与 Codex 专用计划均写入视觉证据（检查 ID、路由/文件、视口、预期与实际指标、差异区域与证据路径），并明示不得通过修改基准、阈值、屏蔽区域或检查开关绕过失败。
- `artifacts clean` 默认只预览，`--apply` 只清理指定任务的视觉产物并保留报告与清理标记，不删正式基准；超过产物预算时阻塞，不删除旧证据换取通过。

### 验收配置健壮性

- 文件不存在：保留原有默认命令检查推导。
- 文件存在但 JSON/schema 无效：输出配置阻塞，**不再静默回退**默认检查。
- 视觉启用且省略 `checks`：继续推导命令检查；显式 `checks: []` 才表示不配置命令检查。
- `extraChecks` 与 `checksMode=replace` 只作用于命令检查，不覆盖视觉门禁。
- `visual` 采用严格字段校验，拒绝拼写错误、重复 ID、无效阈值与冲突选项；启用视觉却没有任何页面或图片规则判为配置错误；每项默认必需，显式 `optional: true` 才降为告警。

## 兼容性与依赖

- **运行时**：非视觉功能保留 Node.js `>=20`；视觉模块要求 Node.js `>=20.3`。
- **图像库为可选依赖**：缺少 `sharp` 不影响 MCP 启动；使用相关能力时明确阻塞并给出 `npm install --include=optional` 说明。
- **固定依赖**：`puppeteer-core@24.43.1`、`@puppeteer/browsers@2.13.2`、`sharp@0.34.5`、`pixelmatch@7.2.0`；配套 Chrome `148.0.7778.97`，安装器从依赖的 revision 映射读取版本，不在业务代码重复维护版本字符串。
- **不自动下载浏览器**：npm 安装与 MCP 启动均不下载浏览器，需显式执行 `tianshu-mcp visual browser install`。
- **平台边界**：Windows 10 x64；macOS 13+（Intel 与 Apple Silicon）；保留 Linux CI 与 Node 20/22/24 测试矩阵。

## 测试与验证

- **Windows 10 本机（10.0.19045 x64，Node 24.18.0，Chrome 148.0.7778.97）**：
  - 全量测试 **486 passed / 8 skipped**（跳过的 8 项为真实浏览器门禁用例，已用 `TIANSHU_VISUAL_BROWSER_TEST=1` 单独跑通：托管浏览器启动与完整解码、三种页面来源、输入/点击/悬停/选项/滚动、整页懒加载、Cookie/localStorage 导入与失效诊断、外部资源允许与拦截、截图差异与规则冻结）。
  - 生产 tarball 安装到不含开发依赖的独立目录后执行视觉冒烟通过：批准基准 → 图片规格检查 → 检出真实像素缺陷 → 离线 HTML 断网可用（状态过滤、透明叠加、区域定位）。
  - `typecheck` / `lint` / `build` / `pack:check` / 严格 stdio 检查通过。
- **CI**：新增 `visual-browser` 矩阵（ubuntu/windows/macos-15-intel/macos-15 × Node 20/22/24），显式安装固定浏览器后跑真实浏览器视觉测试与生产包消费者验收；`build-test` 与 `pack-check` 保留。
- **发布门禁**：release 工作流要求目标提交存在**成功 CI**，且缺少 `GITEE_TOKEN` 时阻塞——不以跳过镜像发行或 Release 运行冒充双仓发布完成。
- **未完成门禁（如实保留阻塞）**：macOS 13+ Intel 与 Apple Silicon 的真实系统/Node/浏览器证据、Windows 10 的完整功能矩阵，以及 v0.5.0 的双仓标签与发行记录核实，以 [验证进度](visual-validation.md) 为准。未执行项不记为通过。

## 升级注意

- **无需迁移**：调用方工具参数、meta 块字段、报告既有字段与验收配置格式保持兼容；视觉字段仅在启用时出现。
- 已有项目默认不受影响（`visual.enabled` 默认 `false`）。
- 首次启用视觉需显式安装浏览器并准备、批准基准；未批准基准的页面检查会阻塞而非假通过。
- 真正需要跨机共享参考图时在检查项里显式指定；否则基准按平台与浏览器类型分区。
