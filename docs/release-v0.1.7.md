## 本次修复：项目文件夹绑定仍失败（v0.1.6 未根治）

实战反馈：绑定 `D:\Trae项目\AI游戏\五子棋` 时，原生对话框出现但**编辑框是空的**，
却直接点了「选择文件夹」。失败任务日志（`tsk_20260908233713_26e336`）：

```
[info] 原生对话框已确认（窗口「Select Project Folder」…），写入路径…
[warn] 原生对话框操作失败：点击确认后对话框仍存在
```

`写入路径…` 之后直接失败——路径没生效，但确认被点了。

### 根因（实测定位）

**MCP 内部传入的是 `normPath()` 规范化路径**（小写盘符 + 正斜杠，如 `d:/Trae项目/AI游戏/象棋`），
而 **Windows 原生文件夹选择器不接受这种形式**。实测对照：

| 写入的路径 | 回读结果 | 点击确认后 |
|---|---|---|
| `d:/Trae项目/AI游戏/象棋`（规范化） | `d:/Trae项目/AI游戏/象棋` | **对话框不关闭**（路径未被接受） |
| `D:\Trae项目\AI游戏\象棋`（原生） | `D:\Trae项目\AI游戏\象棋` | **对话框关闭，绑定成功** |

回读校验通过（因为写进去的就是规范化形式），但选择器拒绝该形式 → 确认无效。

### 修复

1. **写入前转原生路径**：新增 `toNativeWindowsPath()`（正斜杠→反斜杠、盘符大写），
   这是本次真正的根因修复。
2. **写入后回读校验**：用 `WM_GETTEXT` 读回编辑框内容与目标比对；不一致则**重新定位并重试**
   （最多 3 次）；仍不一致**不点确认**并明确报错（避免选中错误目录）。
3. **hwnd 贯穿传递**：footer 点击后探测到的对话框句柄传给写入脚本，只操作该窗口；
   点击后复查「**该 hwnd** 是否已消失」，而不是「任意匹配窗口是否消失」。
4. **自动关闭遗留对话框**：绑定前扫描并 `WM_CLOSE` 上次失败残留的对话框，避免写到旧窗口上。
5. **确认按钮定位加固**：`AutomationId=1` 且 `ControlType=Pane` 之外，增加「矩形位于对话框下半部」
   校验，排除同名 Pane 误命中。
6. 对话框脚本全过程输出（`HWND` / `READBACK` / 结果）写入任务日志，便于下次排障。
