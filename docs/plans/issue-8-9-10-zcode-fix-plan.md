# ZCode #8、#9、#10 联合修复与 v0.3.4 发布计划

## 1. 目标与分析结论

恢复 ZCode 从项目导入、绑定、模型选择，到发送任务、暂停恢复和验收的完整链路。采用已确认的“分阶段自动恢复”，默认最多等待 2 分钟，确需人工处理时才暂停任务。

本次包含以下问题及直接关联缺口：

- [#8](https://github.com/lanlan0811/tianshu-mcp/issues/8)、[#10](https://github.com/lanlan0811/tianshu-mcp/issues/10)：项目回读合并主、备用选择器，其他项目操作按钮造成误判。
- [#10](https://github.com/lanlan0811/tianshu-mcp/issues/10)：PowerShell 探测超时；文件夹操作的内部等待预算与外部进程超时不协调。
- [#9](https://github.com/lanlan0811/tianshu-mcp/issues/9)：无会话锚点的环境恢复跳过会话快照和差集识别，并遗漏原任务上下文、引用。
- #8 同时报告模型文本污染。本地纯函数复核确认：旧模型名、无障碍标签、当前模型名混合时仍会误判，纳入修复，避免绑定通过后继续卡在模型选择。

当前基线：`master`，版本 `0.3.3`，工作区干净；5 个相关测试文件、63 个测试通过，但未覆盖上述真实触发条件。

## 2. 实现调整

**项目定位与模型回读**

- 项目触发器统一按“用户覆盖 → 主选择器 → 精确备用选择器”逐级定位；本级没有可见匹配才进入下一级，本级多匹配则报告歧义。
- 项目点击、菜单定位、绑定回读复用同一规则，移除包含“项目／Project”的宽泛匹配。
- 绑定以当前项目的规范化绝对路径为依据；只有能够唯一关联到目标路径的项目名称才可辅助判断。路径冲突时不能用同名文本覆盖冲突。
- 模型当前值优先读取并解码稳定属性；属性缺失时读取当前可见模型标签、对应标题，最后兼容旧页面。排除隐藏旧值和无障碍提示；证据冲突时明确报错，不直接接受混合 `textContent`。

**首次启动与项目导入自动恢复**

- 将准备、对话框基线采集、打开文件夹、路径提交、绑定确认划分为明确阶段，保存当前阶段和已经确认的结果。
- 探测超时后先复检 CDP、项目列表与绑定状态；已经导入或绑定成功则直接继续。
- 只读瞬态故障允许有限重试。点击、输入、提交超时后先确认副作用；无法证明上次操作未生效时，不重复执行整段导入。
- 使用共同截止时间协调脚本内部等待和外部进程超时；重试不能重置预算。取消任务时中断等待并回收本次辅助子进程。
- macOS 探测失败不得伪装成“没有既有面板”；保留对目标进程、既有窗口和唯一新面板的校验。
- 恢复期间保持任务进行中，通过现有进度通道展示阶段变化和周期进度，日志记录阶段、耗时、尝试次数和错误类别；不消耗代码返修轮数。
- 恢复预算耗尽或出现权限、目标歧义时保留现场，进入可继续的等待状态；任务总时限先到则按任务超时结束。

**会话恢复与发送确认**

- 明确区分“环境恢复后首次派发”和“已有会话续答／返修”，不能仅根据 `ctx.resume` 是否存在决定流程。
- 无锚点的环境恢复在发送前采集会话快照，发送完整原任务、上下文和已验证引用；用户的“已关闭”等确认文本不发送给模型。
- 已有会话续答必须定位原会话；缺失或歧义时不打开最近会话替代。
- 发送确认与会话识别共用一次有界观察窗口，默认最多 60 秒且受任务剩余时间约束。消息出现、输入框清空或运行信号只能证明发送进展，不能单独代替会话定位。
- 优先使用任务标记定位会话；首次派发可使用发送前后唯一的新会话差集。多个候选时继续等待标记消歧，不凭当前活动会话猜测。
- 确认窗口结束仍无法定位时保留 `session_lost`／`send_unknown` 的明确诊断和现场，禁止自动重发。

## 3. 接口与默认值

保持 `run_task`、`continue_task` 的调用参数不变，新增配置沿用现有 `agent-profiles.json` 的 `gui` 配置入口：

| 配置 | 默认值 | 用途 |
|---|---:|---|
| `setupRecoveryTimeoutMs` | 120000 | 从初始化开始到项目绑定完成的总预算 |
| `dialogProbeTimeoutMs` | 30000 | 单次原生对话框探测上限 |
| `dialogOperationTimeoutMs` | 60000 | 单次文件夹操作上限 |
| `setupRecoveryMaxRetries` | 2 | 每个可安全重试阶段的额外重试次数 |

所有等待取配置上限、阶段剩余预算、任务剩余时间的最小值；旧配置自动采用默认值。

新增 `needsUserKind: setup_recovery`，同步任务元数据与驱动返回类型。该类型的 `continue_task` 仅将用户消息视为环境处理确认，重新检查项目状态后继续原任务。权限不足继续使用 `system_permission`。

## 4. 测试与验收

- **真实选择器测试**：通过 DOM 夹具执行实际 CDP 求值表达式，覆盖一个正确触发器与添加、移动、取消按钮共存，覆盖优先级、隐藏节点、重复节点、同名不同路径及中英文页面。
- **模型回归**：覆盖旧值与当前值混合、标签位于文本中间、编码属性、属性缺失和信息冲突。
- **恢复测试**：覆盖首次探测超时后成功、操作超时但实际已绑定、预算耗尽、取消中断、macOS 权限失败及基线未知；断言没有重复点击、提交或返修轮数消耗。
- **完整续跑测试**：经真实任务上下文构建与 ZCode 驱动，验证无锚点环境恢复、延迟会话注册、陈旧活动会话、多个新会话、已有会话续答，以及任务正文、上下文和引用完整且只发送一次。
- **Windows 10 真机**：使用独立数据目录和临时验收项目，覆盖冷启动首次导入、已导入项目复用、无 CDP 实例处理后继续、真实产物落盘与自动验收。模型从测试环境读取并作为参数传入，不写死供应商、安装路径或端口。
- **发布门禁**：类型检查、lint、完整测试、构建、严格 stdio、打包及干净消费者安装全部通过；GitHub CI 的 Windows/macOS/Linux × Node 20/22/24 矩阵通过。
- macOS 本次要求自动测试通过，真机验证明确标记为未完成，不提升现有支持等级。保留真机日志、任务状态、会话 ID、产物与验收报告作为证据。

## 5. 文档、提交与发布

- 实施前将本计划保存为受版本管理的中英文独立文档，放入 `docs/plans/`；不强制添加已被忽略的 `.codex`、`.zcode` 内容。
- 分阶段完成项目与模型回读、会话恢复、初始化恢复；每阶段补齐对应测试和双语文档，通过检查后提交。
- 仅在 `master` 开发，按仓库规则使用 `git add .`、中文提交信息，并依次推送 GitHub 和 Gitee。暂存前检查范围，遵守 `.gitignore`，不修改官网目录。
- 更新双语配置说明、ZCode 使用与故障恢复说明、验收记录和 CHANGELOG；不纳入 #3 视觉验收，也不全面重构其他驱动。
- 目标补丁版本为 `0.3.4`；实施时若已占用，使用下一未占用补丁号。同步包版本、锁文件、生成版本和发布说明。
- Windows 真机验收及对应提交的完整 CI 通过后，将版本标签推送双仓并运行 `release.yml`，核验 GitHub Release 和附件。Gitee Release 若因凭据缺失被跳过，明确记录，不把跳过当成镜像发布成功。
- 本次包含补丁版 Release，**不执行 npm 发布**；发布说明明确 npx 用户尚不会自动获得该版本。出现门禁失败时暂停发布，不覆盖已有标签。
