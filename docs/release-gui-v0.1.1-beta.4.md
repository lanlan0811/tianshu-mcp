# 日志台 0.1.1-beta.4 — 命令层 task_id 越界防护收口（issue #32）

> 完整变更记录见 [CHANGELOG](../CHANGELOG.md)；功能文档见 [docs/gui-log-viewer.md](gui-log-viewer.md)。

这是 0.1.1 线的**安全加固版**，交付 issue #32：把**任务 ID 的字符白名单**从「只有前端深链校验」
下沉到 **Rust 命令层与模块层**，收口四条命令的路径拼装。**无新增功能、无界面变化**——
用户可见行为与 `0.1.1-beta.3` 一致。

---

## 本次修复

### 日志台四条命令的 `task_id` 补齐越界校验（issue #32）

**问题**：`read_events` / `read_baseline` / `export_task_zip` 在拼接 `tasks/<任务>/…` 时对任务 ID
**直接 `join`**，没有走同模块的越界校验函数 `resolve_rel`。这与 `ARCHITECTURE.md` §16.10
「ID 走字符白名单 `[A-Za-z0-9_-]`」的自述**矛盾**——同一条防线在不同命令上口径不一，
**完整性依赖调用方自觉**：新增命令不会自动继承防护。

**修法**（单点收口，不逐处打补丁）：

- `data_home.rs` 新增 **`validate_task_id`**（`[A-Za-z0-9_-]` 白名单，与前端 `core/deeplink.ts` 的
  `TASK_ID_RE` 及 §16.10 同口径）与 **`task_dir`**（先过白名单再拼 `tasks/<id>`），
  作为**「裸任务 ID → 路径」的唯一入口**；
- 三个模块改用 `task_dir`（**防御深度**：即使将来新命令漏了命令层校验，不变量仍在）；
- 命令层（`lib.rs`）四条命令加第一道校验 —— 除 issue 点名的三条外，**一并纳入 `read_report`**
  （它走 `resolve_rel` 本不逃逸，但同样缺字符白名单，同属口径不一致）；
- 非法 ID 在命令层**明确报错**（可诊断），在模块层按既有容错口径**如实留空**
  （基线 `present = false` / 事件空窗口），**不编造**。

**验证中推翻的一个假设**：`export_task_zip` 原有的 `if !task_dir.is_dir()` 检查曾被当作一道有效防线——
实测 **`task_id` 含 `..` 时 `is_dir` 为真**，闸门被穿透。**存在闸门 ≠ 闸门有效**：本次由白名单在
**拼路径之前**拦下，不再依赖目录是否存在。

### 覆盖的攻击面

| 类别 | 样例 | 修复前 | 修复后 |
|---|---|---|---|
| 路径穿越 | `../../outside/evil`、`..`、`../..` | **逃逸**（读到/打包数据目录之外） | 拒绝 |
| 反斜杠穿越（Windows） | `..\..\evil`、`..\../evil` | **逃逸**（仅 Windows 生效） | 拒绝 |
| 绝对路径 | `/etc/passwd`、`C:/Windows` | **逃逸** | 拒绝 |
| NTFS 备用数据流 | `tsk_1:secret` | 未拦 | 拒绝 |
| Windows 非法字符 | `tsk*1`、`tsk?1`、`tsk|1` | 未拦 | 拒绝 |
| 空白 / 点号 | `tsk 1`、`tsk.1`、`""` | 未拦 | 拒绝 |
| Unicode 同形字 | 全角下划线 `tsk＿1`、西里尔 `tаsk_1` | 未拦 | 拒绝 |
| **合法 ID（反证）** | `tsk_20260926135200_d4e5f6`、`vfy_2026-09-26_x1` | 正常 | **正常（零误伤）** |

用**逐字节判定**而非正则：不引入 `regex` 依赖，且 ASCII-only **天然排除** Unicode 同形字、
Windows 非法路径字符与 NTFS 备用数据流。

## 口径说明

- **仅提升防御深度**：正常界面路径**不可能**传入非法 ID（`selectedTaskId` 来自 `list_tasks` 的
  真实目录名；深链另有前端白名单），故本次**用户可见行为 ≈ 0**；改动价值在于让代码与
  `ARCHITECTURE.md` 的承诺一致，并让**新增命令自动继承**防护。
- **一处行为变更**：`read_baseline` 对非法 ID 由「回默认值」改为「报错」。理由是该命令**本就用
  `Err` 表达「任务 ID 缺失」**，非法字符属同类调用方错误，静默降级会掩盖 bug。
- **只读边界不变**：四条命令依旧只读文件 / `stat`，不写任何业务数据。

---

## 边界（本版没做什么）

- **不新增功能、不改界面**：无新页面、新分区、新命令；i18n 零新增键；`src/api` 方法签名不变。
- **不重构内部派生路径**：`scanner.rs` / `insights.rs` / `search.rs` 中由 `read_dir` 派生的
  `task_id`（来自 `file_name()`，结构上不含分隔符，且已按 `tsk_` / `vfy_` 前缀过滤）**不属外部输入**，
  有意不改。
- **不做**：清理 / 删除入口、任务续跑与返修、通知 / 托盘角标、本地全文索引（沿用既有决策）。
