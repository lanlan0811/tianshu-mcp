# Qoder CN GUI 适配

Qoder 适配器通过桌面应用的 CDP 界面执行开发任务，并复用天枢 MCP 的客观验收与返修引擎。仅支持 Qoder CN，不能用国际版或任意同名窗口替代。Windows 真机验收完成前，不应把自动化测试通过视为正式兼容性结论。macOS 当前为 `research`，拒绝派发。

## 调用

```json
{
  "agentId": "qoder",
  "projectPath": "D:\\projects\\example",
  "planDoc": "plans/development.md",
  "task": "根据计划文档实现项目并补充测试",
  "modelSource": "custom",
  "model": "用户已经配置的模型名称",
  "reasoningLevel": "极高",
  "autoFixRounds": 3
}
```

`projectPath` 必须是已有目录，`planDoc` 必须是可读取文件；相对计划路径基于项目根目录解析。适配器会发送完整项目路径、完整计划路径与任务要求。不会替用户创建缺失的磁盘目录。

模型参数均可省略。省略模型、思考等级时沿用当前值；指定模型但不提供 `modelSource` 时，必须在“默认”和“自定义”两组中唯一精确匹配。重复名称需要指定 `default` 或 `custom`，不能仅靠模型名称猜测来源。

支持输入 `低/low`、`中/medium`、`高/high`、`极高/xhigh`、`最大/max`、`关闭思考/off`。可用等级以当前模型在“模型管理”中实际展示的选项为准；某个自定义模型不一定提供全部等级。适配器拒绝不支持的档位，不自动降级。

思考等级通过“模型管理”设置、保存，再重新打开回读。修改会保留为 Qoder 全局偏好，影响之后的任务；执行报告记录实际模型与等级。权限模式沿用当前界面设置，不自动切换“完全访问”。

## 安装与工作区

发现顺序为显式 `gui.exePath`、优先盘候选位置、注册表和快捷方式、其他磁盘与标准位置。显式路径无效时直接报告错误，不偷偷换用另一份安装。路径和探测预算来自 profile 配置，不依赖某个用户的个人目录。

可连接的 Qoder 主工作台允许复用。发现已有实例但没有可用 CDP 时保留现场，返回 `needs_user`，由用户保存工作并处理实例后调用 `continue_task`。不会关闭或重启已有实例。

工作区使用完整路径确认身份。名称只作为候选，不作为目录身份；中文、空格、同名目录均需核对实际路径。未登记的已有目录通过“新的任务 → 工作区入口 → 新建工作区 → 添加可读写文件夹 → 选择文件夹 → 创建”登记。原生对话框必须同时匹配进程归属、新出现的窗口和标题，随后回读源目录。

初次任务新建会话。返修和续答恢复持久化的原会话，并重新核对目录；不能确认原会话时停止派发。

## 等待与恢复

`query_task` 可以查看等待原因、会话标识、实际模型、等级和停止结果。生成按钮、工具执行、流式活动都属于运行证据；界面静止、旧回复中的“完成”、连接断开均不是本轮完成证据。只有确认本轮用户消息对应的回复结束且运行信号消失后，才进入客观验收。

- **审批、登录等环境等待：** 在 Qoder 中处理后调用 `continue_task`，适配器只恢复观察，不把“已处理”等文字发送给模型。不会自动批准、切换模型或重发开发任务。
- **Agent 提问：** 通过 `continue_task.message` 提供明确答案。单题可用普通文本；多题使用 JSON 对象，以界面上的完整问题文字为键。多选答案可使用选项文字数组。
- **发送或答案提交不明：** 提交前持久化检查点；没有确认回执时不自动重发。请先检查原会话，再按任务报告处理。
- **取消、超时：** 只停止已绑定的原会话并核对停止结果。`guiStop.idle=false` 表示未能确认停止，不能据此认定任务已经结束或继续派发新工作。

多题回复示例（作为 `message` 的字符串内容传入）：

```json
{
  "选择开发语言": "TypeScript",
  "需要哪些测试": ["单元测试", "集成测试"]
}
```

适配器先检查全部题目与答案，再操作答题控件，不接受推荐项或默认项来代替缺失答案。题目发生变化、缺少答案或选项不存在时保留等待。

## 验收与返修

Qoder 自述完成不能代替验收通过。验收使用项目配置的检查命令、变更分析和已启用的视觉检查。失败后先在 MCP 任务目录生成 `rework-<taskId>-r<round>.md`，随后向原会话发送失败说明、计划文件名、绝对路径及全文。即使计划文件在项目目录外，也有完整正文可供执行。

默认自动返修 3 轮，`autoFixRounds` 范围为 0–10。达到上限保留验收报告，进入需关注状态。审批、连接、登录等基础设施问题不触发代码返修。

## 验证边界

构建后可运行 `npm run probe:qoder -- install` 检查安装发现，或 `npm run probe:qoder -- state --port 9777` 检查已有实例（端口按实际配置替换）。探针不启动应用、不发送任务、不点击审批；连接时可能将已有工作台置前。输出省略任务及回复正文，分享路径和会话标识前仍应检查个人信息。

自动化测试使用可控 GUI 替身，不依赖登录或真实桌面。2026-09-22 在 Windows 10 / Qoder CN 0.3.4 上通过公共 MCP 工具完成真机验收：已有工作区使用默认模型 Qwen3.8-Flash / 低完成开发与验收；新登记工作区使用自定义模型 deepseek-v4-flash / 高完成开发、受控错误验收失败、生成计划、原会话返修和再次验收。工作区外计划读取由用户审批，恢复时未重发消息。见[脱敏状态与报告](qoder-evidence/windows-smoke.json)、[默认模型设置截图](qoder-evidence/default-model-settings.png)、[自定义模型设置截图](qoder-evidence/custom-model-settings.png)。模型名称仅为本次样例，不是默认要求。macOS 的路径及平台分支测试不代表真实 GUI 已通过验证。
